Phase 0: Project Scaffolding

Goal: one installable package with one entry point, instead of flat disconnected scripts.

  src/anpr/
    __init__.py

    vehicle_detector.py  # YOLO26 + ByteTrack wrapper
    plate_detector.py    # secondary YOLO26 on vehicle crops

    formatter.py            # raw OCR text -> standard VN plate format

  tests/
  logs/

  .vscode/

  • config.yaml holds model paths, target COCO classes, confidence thresholds (vehicle/plate/OCR), and output/log paths — no hardcoded video path in source.
  • cli.py exposes --video (required), --config (defaults to the repo-root config.yaml), and --output.

Phase 1: Environment & Dependency Setup

Goal: a reproducible, lightweight Python environment using uv.

  • pyproject.toml builds src/anpr as an installable package (hatchling + [tool.uv] package = true); uv sync installs it editable with a uv run anpr console script.
  • Computer vision: opencv-python, numpy (transitive via ultralytics).
  • Detection/tracking: ultralytics (YOLO26 + ByteTrack).
  • OCR: paddleocr>=2.7,<3 and paddlepaddle>=2.6,<3 — pinned below the 3.x line on purpose. PaddleOCR 3.x renamed constructor args (use_angle_cls → use_textline_orientation, dropped show_log) and its default pipeline (doc-orientation + doc-unwarping + detection + recognition) is noticeably heavier than the 2.x path this project's ocr.py is built against. One OCR engine only — no EasyOCR fallback.
  • Config/CLI: stdlib argparse + PyYAML.
  • Persistence: stdlib sqlite3 (no new dependency) — for Phase 4.
  • Dev: pytest, to be added when Phase 5's unit tests land.
  • Hardware acceleration (Intel Core Ultra 7): openvino, to be added for Phase 6.
System requirement paddlepaddle requires the system OpenMP runtime libgomp.so.1. Without it, import paddle fails with ImportError: libgomp.so.1: cannot open shared object file. Install via sudo apt-get install -y libgomp1 before running the pipeline on a new machine.

Phase 2: Model & Dataset Acquisition

Goal: detection weights and training data for Vietnamese plates, covering white (personal), yellow (commercial), and blue (government) backgrounds.

2.1 Vehicle detection model

models/yolo26n.pt — pre-trained YOLO26, filtered to COCO classes 2 (car), 3 (motorcycle), 5 (bus), 7 (truck) via config.yaml's detection.target_classes.

2.2 License plate detection model

models/license_plate_detector.pt — custom-trained YOLO26, trained via train_model.py against input/datasets/vn_license_plate_dataset/ (a Roboflow "Vietnam license plate" export, CC BY 4.0, single class plate). Currently 50 epochs, imgsz=416, batch 8, CPU.

Where to look for more data
  • Roboflow Universe — search "Vietnamese license plate"; check each project's license before use beyond personal/research.
  • Kaggle — search "Vietnamese license plate detection/recognition" for datasets with both detection boxes and OCR ground truth.
  • GitHub — repos/topics like vietnamese-license-plate or "Vietnamese ALPR YOLO" often bundle or link to a labeled dataset. Verify the license before reuse.
  • Hand-label a supplement. Public datasets skew heavily toward white personal plates. Capture footage containing commercial/government plates and label a few hundred with Roboflow's annotate tool, CVAT, or LabelImg to fill the yellow/blue gap.
  • Still needed: verify the current dataset's white/yellow/blue balance — not yet checked.
  • Still needed: stratify train/val/test by plate color so Phase 7 can report per-color recall, not just an aggregate number.

2.3 OCR engine

PaddleOCR's default multilingual detection + recognition models (en) — handles VN plates' alphanumeric character set; no custom OCR training needed.

Phase 3: Core Pipeline Integration

Goal: one video-processing loop in pipeline.py connecting detection, tracking, deskewing, and OCR.

  1. Detection & tracking (ByteTrack): vehicle_detector.py's VehicleDetector.track() calls model.track(frame, classes=target_classes, persist=True), with target_classes sourced from config.yaml.
  2. Plate extraction: crops the vehicle box and runs plate_detector.py on the crop.
    Known issuepipeline.py takes plate_results[0].boxes.xyxy[0] as "the" plate box. Ultralytics does not guarantee that ordering is confidence-sorted. Should explicitly select argmax(boxes.conf) when more than one plate candidate is returned.
  3. Plate-type & layout classification (not yet implemented): from the plate crop, determine
    • Layout — 1-line vs 2-line, via bounding-box aspect ratio (1-line plates ≈ 4.5:1 width:height; 2-line motorbike plates ≈ 1:1–1.5:1). Feeds the OCR line-sort step instead of relying on however many text regions PaddleOCR happens to return.
    • Background color — white / yellow / blue, via an HSV color mask sampled from the plate crop's background pixels. Needed before preprocessing can be color-aware (see step 5).
  4. Deskewing (deskew.py): find_plate_corners_from_crop + four_point_transform, called right after the plate crop is extracted. Falls back to the raw crop when 4 corners aren't found (common on low-contrast crops).
  5. Preprocessing (not yet implemented): plate crops currently go straight from deskew to OCR with no contrast/binarization step. Build this only once step 3's color classification exists: resize (bicubic) → grayscale → bilateral denoise → sharpen → Otsu binarize, with the threshold direction (THRESH_BINARY vs THRESH_BINARY_INV) chosen from the detected plate color. A single fixed threshold direction breaks blue plates (light text on a dark background inverts). Also worth confirming empirically whether binarizing helps at all — PaddleOCR's recognizer is a CNN trained on natural grayscale/color crops, and hard binarization can hurt it rather than help, unlike with classical OCR engines.
  6. OCR & formatting: ocr.py's vn_plate_parser runs PaddleOCR on the (deskewed) crop, sorts detections top-to-bottom, concatenates, and passes the cleaned text to formatter.py's vn_plate_formater.
    Known issuevn_plate_formater slices by string length (if length == 8 → …, elif length == 9 → …) with no character-class check, so an 8- or 9-character OCR misread is silently accepted as a valid plate. Should be replaced with an explicit regex per known VN format (e.g. ^\d{2}[A-Z]-?\d{1,2}?\d{3}\.\d{2}$ after cleaning), rejecting to "no read" when nothing matches.

For manual verification, every confirmed plate read saves its exact (post-deskew) crop to output/snapshots/frame{N}_track{id}_{plate_text}.jpg — so the OCR output can be eyeballed against the source image.

Phase 4: Persistence & Logging

Goal: give "anpr-track" something to track — a structured record that survives after the process exits, not just a console printout.

src/anpr/storage.py is currently an empty stub. Target design:

  • Storage: SQLite (output/detections.db) via stdlib sqlite3.
  • Schema (one row per confirmed read, not per frame):

Note: snapshot images are already being written (see Phase 3); storage.py just needs to record the path alongside the rest of the row.

Phase 5: Robustness Refinements

Goal: reduce false/garbage reads before they ever reach persistence.

track_state.py currently implements only a first-successful-read cooldown (has_plate / get / set over a plain dict) — not the voting buffer below.

  1. Frame voting: maintain a short buffer (last 3–5 OCR attempts) per track_id; keep the most frequent formatted-and-validated result rather than the first non-empty one.
  2. Confidence-gated cooldown: only stop re-running OCR on a track_id once the voted result has both (a) hit a minimum vote count and (b) passed the Phase 3 format regex.
  3. Unit tests (tests/ is currently empty): formatter.py's regex validation and track_state.py's voting logic are pure functions — cheap to cover with pytest once it's added as a dependency.

Phase 6: Hardware Optimization (Intel Core Ultra 7)

Goal: move from MVP to real-time performance using OpenVINO, sequenced after the pipeline is correctness-verified (Phase 7 gate).

  1. Export YOLO to OpenVINO: convert both YOLO26 models to IR format — yolo export model=yolo26n.pt format=openvino (and the same for license_plate_detector.pt).
  2. NPU/iGPU offloading: point Ultralytics inference at the exported IR directory — YOLO("yolo26n_openvino_model/", task="detect") — and select the Arc iGPU or NPU device explicitly.
  3. PaddleOCR OpenVINO backend: enable OpenVINO execution in PaddleOCR's inference parameters for the recognition phase.

Phase 7: Testing & Validation

Goal: validate accuracy against real-world conditions with numbers, not just "looks about right."

  1. Test set: 3 distinct video types — daytime clear, nighttime (headlight glare), heavy traffic (occlusion). input/videos/ is currently empty; when sourcing, aim to cover all three plate colors in scope.
  2. Success criteria:
metrictarget
Plate detection recall (daytime)≥ 90%
Plate detection recall (night / occluded)≥ 70%

End-to-end latency, pre-OpenVINO (CPU)baseline measurement only, no target

  1. Per-plate-color breakdown: report recall/accuracy separately for white, yellow, and blue plates — depends on Phase 2's color-stratified split.
